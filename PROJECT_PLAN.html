핵심 관계 설명

관계 설명 왜 이렇게?
User → TastingNote (1:N) 한 유저가 여러 노트 작성 노트 조회 시 본인 것만 보이도록 분리
User → UserPreference (1:N) 취향 키워드가 유저별로 따로 누적 지금은 전역이라 A·B 취향이 섞임. 분리 필수
TastingNote → MasterWhisky (N:0..1) 마스터DB에 있는 위스키면 연결, 없으면 null 마스터에 없는 위스키도 노트 작성 가능하게 선택적
UserPreference.version 낙관적 락을 위한 버전 컬럼 동시 요청 시 같은 키워드 점수를 두 스레드가 동시에 덮어쓰는 문제 방지

단계별 구현 계획 — 무엇이 왜 추가되는가

✅ Phase 0 · 완료

기본 구조 정비

  • 완료패키지 통일 (domain → entity)
  • 완료DTO 분리 (Request / Response)
  • 완료GlobalExceptionHandler
  • 완료TastingNote ↔ MasterWhisky @ManyToOne
  • 완료MasterWhisky @Builder 패턴
  • 완료DataInitializer → ApplicationRunner
  • 완료테스트 환경 수정 (H2, @ActiveProfiles)
✅ Phase 1 · 완료

회원 시스템 (Spring Security + JWT)

  • 신규 엔티티User (email, password, role)
  • 신규AuthController (register, login)
  • 신규JwtTokenProvider / JwtAuthFilter
  • 신규SecurityConfig (공개/보호 URL 설정)
  • 수정TastingNote에 user_id FK 추가
  • 수정UserPreference에 user_id FK 추가
  • 수정모든 서비스에 현재 유저 필터링 추가
왜 가장 먼저?
지금은 모든 노트·취향이 전역(누구 건지 모름). 회원이 없으면 이후 동시성·캐싱·추천 모두 의미 없음. 데이터 모델의 뼈대가 되는 단계.
✅ Phase 2 · 완료

동시성 제어 + 성능 최적화

  • 수정UserPreference에 @Version 낙관적 락 적용
  • 신규PreferenceUpdateService — 최대 10회 재시도 + 랜덤 딜레이
  • 신규@Lazy self-injection으로 순환 참조 + 트랜잭션 분리 해결
  • 테스트CountDownLatch + ExecutorService 동시성 검증
  • 수정키워드 저장 CompletableFuture 병렬화
  • 측정순차 46ms → 병렬 14ms (3.3배 단축, PostgreSQL 실환경)
왜 이 시점에?
회원 분리 후에야 "같은 유저의 동시 분석 요청"이 의미 있는 시나리오가 됨. 낙관적 락 + 재시도 + 병렬화까지 수치로 증명 가능해 포트폴리오 핵심 항목.
✅ Phase 3 · 완료

비동기 AI 분석 (@Async)

  • 신규AsyncConfig (ThreadPoolTaskExecutor 설정)
  • 수정WhiskyAnalysisService에 @Async 적용
  • 수정analyzeNote API → 202 Accepted 즉시 반환
  • 측정스레드 풀 크기별 처리량 비교
왜?
Ollama 분석은 3~10초 소요. 지금은 AI가 끝날 때까지 요청이 블로킹됨. 비동기로 바꾸면 응답성 향상 + 스레드 자원 낭비 감소.
🔜 Phase 4 · 다음

Redis 캐싱 (추천 API 최적화)

  • 인프라Redis 도입 (docker-compose로 로컬 실행)
  • 신규CacheConfig 설정
  • 수정WhiskyRecommendService에 @Cacheable 적용
  • 수정취향 업데이트 시 @CacheEvict (캐시 무효화)
  • 측정캐시 적용 전/후 응답시간 비교
왜?
추천 계산은 무겁지만 취향이 바뀌기 전까지 결과가 동일함. Redis에 결과를 저장하면 DB 조회 없이 수 ms로 응답 가능.
📌 Phase 5

검색 고도화 (QueryDSL)

  • 도입QueryDSL 의존성 + QueryDslConfig
  • 수정MasterWhiskySearchService 동적 쿼리로 교체
  • 신규복합 조건 검색 (카테고리 + 가격 + 향 키워드 동시 적용)
왜?
지금은 조건 하나씩만 검색 가능. "스카치 + 10만원 이하 + 피트 향" 같은 복합 조건을 if 분기 없이 처리. 코드 유지보수성도 향상.
🖼 Phase 6

이미지 업로드

  • 신규FileUploadController + FileUploadService
  • 수정MasterWhisky에 imageUrl 컬럼 추가
  • 저장소로컬 파일 저장 → 추후 S3 확장 고려
  • 신규Multipart 파일 처리, 확장자 검증
왜?
노트·위스키 카드 UI에 이미지 표시. S3 같은 외부 저장소 연동 구조로 설계하면 "파일 관리 경험"도 추가됨.
